● लोकल असिस्टेंट
नमस्ते! मैं आपके सॉफ्टवेयर का कंट्रोल असिस्टेंट हूँ।
उदाहरण: “स्टॉक लिस्ट खोलो”, “कितनी बुकिंग हैं?”, “100 कुर्सियों की स्टॉक एंट्री तैयार करो”। सेव/भुगतान/डिस्पैच जैसी महत्वपूर्ण कार्रवाई से पहले आपको विवरण जाँचकर खुद पुष्टि करनी होगी।
🔐 सुरक्षा: यह बिल्ट-इन कमांड असिस्टेंट है, अपने-आप में इंटरनेट-आधारित/मानव-जैसी AI सेवा नहीं। यह केवल इस फ़ाइल में उपलब्ध कमांड और सेव डेटा पर काम करेगा। पैसे, रिकॉर्ड सेव करने, बुकिंग मंज़ूर करने या स्टॉक बदलने से पहले स्क्रीन पर विवरण जाँचें।

🏢 शॉप ब्रांडिंग & लोगो ▼

🔐 एडमिन पासवर्ड और सुरक्षा कुंजी ▼

एडमिन यूजर आईडी और पासवर्ड यहाँ सेट या अपडेट करें। दोनों अलग-अलग रखें।

💳 वास्तविक पेमेंट गेटवे सेटिंग्स ▼

यहाँ केवल सुरक्षित बैकएंड के endpoint URLs रखें। Secret Key, Private Key या webhook secret इस HTML या ब्राउज़र में न डालें।

भुगतान तभी Verified होगा जब सर्वर गेटवे से पुष्टि करे और webhook signature सत्यापित करे। केवल ग्राहक का UTR, स्क्रीनशॉट या लौटकर आने वाला URL पर्याप्त प्रमाण नहीं है।

🔐 वास्तविक ग्राहक OTP सेवा ▼

वास्तविक OTP के लिए अलग HTTPS Request और Verify endpoints जरूरी हैं। आपके मौजूदा backend का https://tenthouse.vercel.app/api/send संदेश भेजने वाला endpoint है; इसे OTP Verify URL की जगह नहीं डालना चाहिए। OTP चलाने के लिए backend में /api/otp/request और /api/otp/verify routes भी उपलब्ध होने चाहिए। OTP को HTML/ब्राउज़र में generate या expose न करें।

सुझाव: पहले backend URL सेट करके टेस्ट करें। backend तैयार न हो तो OTP अनिवार्य न करें, वरना ग्राहक बुकिंग सबमिट नहीं कर पाएँगे।

💬 WhatsApp Cloud API सेटिंग्स ▼

Access Token और Webhook Verify Token यहाँ नहीं रखें। उन्हें Vercel के Environment Variables / सुरक्षित Backend में रखें। ये दोनों फ़ील्ड तभी काम करेंगे जब Backend API कॉन्फ़िगर हो।
